# Meloop 開発ノート — 3人で、3週間

このブランチの画面は学習用の土台です。サンプル投稿・フォロー・リアクションはブラウザのメモリ上だけで、更新するとリセットされます。実在の利用者の投稿ではありません。認証は未接続です。mainへの直接pushや自動マージはしません。

## 分担と到達目標

| 担当 | 1週目 | 2週目 | 3週目 |
| --- | --- | --- | --- |
| A：認証・プロフィール | Supabase Authの登録／ログイン、セッションを理解 | プロフィールの取得・編集、ログアウト | 未ログイン時・エラー時の確認 |
| B：投稿・つながり | posts / follows / reactions のテーブル設計 | 投稿・フォロー・絵文字リアクションを保存 | 他のアカウントとの共有・RLS確認 |
| C：音楽・画面 | Spotify検索とUIを理解 | 曲を選んで投稿、試聴可能な曲の再生 | スマホ・キーボード・アニメーション確認 |

最初に小さいPRを1本ずつ作り、他の1人が確認してから自分たちでマージ。3週目は新機能を増やさず動作確認と発表準備へ。おすすめ機能やチャットは今回の範囲外にすると間に合わせやすいです。

## 穴埋めする場所

| ファイル | 役割 |
| --- | --- |
| `app/page.tsx` と各画面の `page.tsx` | URLと画面の対応 |
| `components/music-app.tsx` | 共通ナビ、ホーム、検索、認証フォームなど。`Player` / `Reactions` / `Following` の関数名で探す |
| `app/globals.css` | 色・余白・スマホ表示・アニメーション。`--pink` などの変数から変更すると簡単 |
| `lib/workshop/data.ts` | サンプル投稿とユーザー、共通の曲データ型 |
| `lib/workshop/actions.ts` | 認証・投稿保存の穴埋め入口 |
| `middleware.ts` | 設定があるときのSupabaseセッション更新。設定なしでは公開サンプル表示のみ |

見出しには手書きフォントYomogiを同梱しています。`public/fonts/Yomogi-LICENSE.txt` を残してください。本文は読みやすいシステムフォントです。

`lib/workshop/actions.ts` の `TODO(A)` / `TODO(B)` を検索してください。未実装部分は明示的にエラーを返します。成功したふりをする認証は入れていません。`components/music-app.tsx` のローカル状態を、保存したデータの取得・更新に置き換えます。

1. A：ブラウザ用Supabaseクライアントを追加し、signUp / signInWithPassword / signOut を接続。登録後のメール確認を扱う。パスワードは自分のテーブルに保存しない。
2. A：profiles を auth.users のIDに紐付け、表示名と自己紹介の保存・取得を実装。
3. B：posts に author_id / spotify_track_id / 本文 / created_at を用意し、取得と投稿を実装。ブラウザから渡されたユーザーIDを信用せず認証ユーザーを確認。
4. B：follows は follower_id + following_id、reactions は user_id + post_id + emoji に一意制約を付ける。同じ操作を繰り返して重複しないようにする。
5. B：各テーブルでRLSを有効にし、「他人のデータを更新・削除できない」ことを2つのアカウントで検証。service_role キーをクライアントへ渡さない。
6. C：検索結果から選択した曲を投稿に含める処理を接続。SpotifyのID・曲名・アーティスト・リンクを保存し、音源ファイルを保存しない。

## 音楽の再生について

既存の `/api/spotify/search?q=曲名やアーティスト名` を使用します。Spotifyの `preview_url` は存在しない曲が多く、APIやアプリのアクセス条件によって取得できない場合もあります。必ず数秒再生できると約束できません。このUIはURLがある曲だけ最大15秒試聴し、ない曲はSpotifyへ案内します。再生失敗時も案内します。サンプル投稿には音源を入れていません。

Spotify全曲の再生はこの検索APIとは別の仕組みです。Web Playback SDKなどにはPremium・認証・利用条件が関わります。今回は「取得できる試聴＋Spotifyで聴く」を最低目標にしてください。公開前にSpotifyの最新の開発者ポリシー、プレビュー利用条件、表示・帰属要件を確認し、利用可能な方式を決めてください。

## 起動・確認

Node 24で `npm ci`、`npx next dev`。設定のない環境でもサンプル画面を見られます。実サービス接続には `.env.local` または環境設定に `NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_ANON_KEY`、`SPOTIFY_CLIENT_ID`、`SPOTIFY_CLIENT_SECRET` を設定します。秘密値をGitに入れないでください。

検査：`npx next typegen` → `npx tsc --noEmit`、`npx eslint .`、`npx next build`。依存関係やlockfileはこのUI作業では変更していません。

手動確認：6画面の移動／空の検索／検索失敗／検索結果ゼロ／試聴URLなし／再生失敗／絵文字の選択と解除／フォロー切替／再読み込みでデモ状態が消えること／認証未実装の案内／スマホ幅／動きを減らす設定。実装後は別ブラウザの2ユーザーで投稿の共有とアクセス制御を確認。
